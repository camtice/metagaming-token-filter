What this filter is for

We are building a token-level filter for pretraining data whose job is to keep language models from learning to metagame — to reason about the evaluation and oversight apparatus around them (eval awareness, grader/harness reasoning, reward-process reasoning, sandbagging toward a grader). The framing follows Rathi & Radford, “Shaping capabilities with token-level data filtering”: label forget tokens in pretraining data and mask them during training.

Your deliverable is the token classifier itself, built without SAEs: a model or function that maps raw text to per-token forget flags (or probabilities), fast enough to run over pretraining-scale corpora. Method is your call — a fine-tuned small encoder as a token tagger, an embedding model with a classification head, a lexical/hybrid system, anything — trained on the labeled data below. The owner’s existing labeler (an SAE feature ensemble, kept as the reference bar — see background) is deliberately not part of your toolchain.

The project is recall-first: a missed metagaming token teaches the model the behavior, while a wrongly masked token only wastes a sliver of training data. Our headline metric is therefore F2 (recall weighted 4× precision), always reported alongside the false-positive rate on real retain text, which is the capability-cost readout.

Scope: what is forget, what is retain

The scope has two layers. The first is the behavior itself, marked by human span annotations on real documents. The second is content that teaches the behavior, defined by a 338-term blocklist in five categories. The blocklist (regex_v3.py, in the owner’s handoff bundle; word-bounded terms, per-term case sensitivity) defines the category vocabulary and is a legitimate feature source for a lexical baseline.

What to train on. Gold forget = the annotations span labels (spans are [start_word, end_word_exclusive, category] over text.split()). Silver forget = the dense c1–c4 docs treated as wall-to-wall positive (this is also how the main metric counts them; c5 is retain). Retain = the five ctl_* configs plus the non-span tokens of annotated documents. The big unannotated pools (kimi chat/agentic, westover, needham) are free for pseudo-labeling, augmentation, or hard-negative mining. On request the owner can also export the reference labeler’s token flags over any of these pools as distillation targets — using those is allowed (they are labels, not SAEs).

Background: the SAE reference labeler (not your toolchain)

The owner’s current labeler is an ensemble of 187 Gemma-Scope SAE features (“D2”) applied with Rathi’s firing rule — chosen by constrained search against the same labels and metric you will use. It exists so the non-SAE filter has a concrete bar to beat, and so hard cases can be cross-checked. You do not need GPUs, SAE weights, or any of its code; if a comparison on specific documents would help, ask the owner for its token flags. One transferable lesson from its post-mortems: features/cues that key on assistant-answer register (scaffolding, formatting, function words) rather than topic buy recall on chat spans but flood ordinary instruct data — watch for the same failure mode in a trained tagger.

Evaluation protocol (manifest v4 · metric v5)

All comparisons run on a sealed three-way split of the annotated + control data (data/splits/split_manifest_v4.json, membership pinned to revision f7ae7700):

SplitDocsContentsUsage
TEST820annotated docs + 150 dense + 625 retain controls (incl. SWE)iterate freely
VAL-A814in-distribution mirror of TEST (same strata, incl. dense)sealed frozen sets only, access-logged, output never displayed
VAL-B57the fully-labeled frontier CoT rollouts — highest-quality validationsealed same lock
  • Main metric (protocol v5, 2026-08-15): token-level P / R / F2 where forget = human span tokens plus every token of the dense c1–c4 docs (all-forget; c5 excluded as retain). Reported alongside: the human-span-only metrics (secondary), per-register span recall, and the token flag rate on the 625 assumed-clean controls (target ≤ 10%, reported per config). Aspiration set by the owner: recall ≥ 0.90 at FP ≤ 0.10.
  • Scoring your classifier: the same definitions apply to any per-token predictions — no SAE machinery involved. Ground-truth spans are whitespace-word indexed; score at the word level (or map to your tokenizer consistently). The owner can supply a prediction-file scorer and a word-level rescoring of the reference labeler so the bar is exactly comparable (published reference numbers were computed on subword tokens).
  • Training exclusion rule: never train, tune, or model-select on any VAL-A / VAL-B document — including their rows in the annotations config (the frontier rollouts are fully labeled but sealed). TEST is the iterate-freely split; validation is spent once, by the owner, on your frozen final classifier.
  • Provenance tags: every doc carries seeded_random / kw_enriched / assumed_clean / assumed_forget, so metrics can be reported with enrichment and assumptions separated.

The numbers to beat (TEST, reference labelers)

Update (2026-08-19): the SAE-side reference has moved since this table was compiled. The current best labeler is a pre-registered ratio rule — keep an SAE feature if it fires ≥10× more per token on forget training text than on retain controls, and require 4 selected features to co-fire on a token before it seeds a label (paper default is 2) — with no combinatorial optimization. On a proper train/test split inside TEST it reaches held-out generalization F2 ≈ .82 at ~1% control FP (haiku-v8 judge pool, 65k SAE, 682 features). Under the same split, direct optimization generalizes worse than this rule, and the judge-pool stage was shown to be necessary (a no-judge variant collapses on real text). Getting started

  1. Access: HF org access to camgeodesic/metagaming-labeling is the only credential you need. No GPUs are required unless your chosen method wants them.
  2. Load the data: 
    from datasets import load_dataset
ds  = "camgeodesic/metagaming-labeling"
ann = load_dataset(ds, "annotations")["eval"]        # spans over text.split():
                                                     # [start_word, end_word_exclusive, category]
d1  = load_dataset(ds, "dense_c1_ai_evals")["eval"]  # ...c2_ai_safety, c3_human_oversight,
                                                     #    c4_training_mechanics (c5 = retain)
ctl = load_dataset(ds, "ctl_dolci_instruct")["eval"] # + dolci_think, fineweb, wildchat, swe_tests
    Annotation ids name their source config and document; the split manifest (provided by the owner) tells you which ids are TEST vs sealed validation.
  3. Respect the split: build train/dev material from TEST + the unannotated selection pools only; treat every VAL-A/VAL-B id (and its annotation rows) as radioactive.
  4. Evaluate at the token level against the v5 metric (main F2, control FP by config, span metrics secondary). The owner supplies the prediction-file scorer and the reference predictions for exact comparability.
  5. Submit: when you have a frozen classifier you believe in, hand the owner the model (or its TEST + validation-corpus predictions); the owner runs the one sealed validation pass and reveals all numbers together.
  6. Labels: new annotations are made in the “Metagaming Token Labeler” artifact (browser tool, drag word-spans, autosaves locally, exports JSON); ask the owner for a share link if you want to add labels — more chat-register annotation is the highest-leverage data work.
Handoff boundary: everything you need lives in the HF dataset plus a small handoff bundle from the owner (split manifest, scorer, blocklist, reports). The owner’s full project directory (SAE code, activation harvests, sealed outputs) is deliberately not part of this handoff — if something seems missing, ask rather than dig.
